# B02 blind replay — honest report

Part: OOM-B02, three-arm robot-vacuum side brush. This report compares the golden record, a
blind replay of the new `stl-re-*` skills, and a blind replay of the baseline skill, all against
the same golden answer key.

Replay artifacts (reports, gate.json, verdicts) are copied under `evals/replay/artifacts/`. Paths below like `B02/new_run/qa/gate.json` map to `artifacts/B02/new/gate.json`.

## 1. Setup

- **Inputs given to each blind run:** a full-resolution scan (`input/scan.stl`, 798,874 faces),
  18 caliper/identity photos, and a caliper reading sheet (`input/MEASUREMENTS.md`, D-01..D-12,
  7 confirmed + 1 soft + 4 unassigned). No caliper session was run; the owner directive was
  proceed-without (`B02/new_run/DECISIONS.md` MEASUREMENTS entry; `baseline_notes.md`).
- **New skills used:** `stl-re-intake-datum`, `stl-re-measure-intent`, `stl-re-rebuild-build123d`,
  `stl-re-verify`, orchestrated by `stl-re-orchestrate`. Frozen at commit `ccbb063` — before the
  Phase 4 review-fix commits (`a2c95be`, `5ee60da`, `69f7b5e`, `d860e18`, `a542434`).
- **Baseline skill used:** the single `baseline/skills/stl2step-build123d` skill, one agent, no
  separate intake/measure/verify stages (`baseline_notes.md`).
- **Owner time-box:** the new-skills run was capped at 2 loops (tighter than the skill's 3)
  (`B02/new_run/DECISIONS.md` OTHER entry).

## 3. What the new skills did better, and worse

Better: the new skills used the caliper D-01/D-02 arm section (5.33 × 4.07) directly, where the
baseline chose 5.8 × 3.3 from scan PCA and contradicted the confirmed calipers
(`baseline_notes.md`). The new run also ran a real CHK-ACHIEVABLE two-jaw check on D-05 (the same
lesson the golden itself learned the hard way in it1, `analysis/golden/OOM-B02.md` §8), produced a
named-interface breakdown with masked/unmasked numbers side by side (the golden's own honesty
practice), and declared five limitations each with a re-run trigger (`qa/VERDICT.md`). The
baseline produced only a flat pass/fail with no per-interface or per-mask accounting, and its own
gate ran out of memory on the full closest-point query (`baseline_notes.md`).

Worse: the new B02 run still finished **BAND_NOT_MET**, worse than the golden's eventual
APPROVED. Two misses stand out. First, D-05/F06: even after the achievable-window fix, the CAD
(25.014) sits only 0.03 mm from the scan's own achievable minimum, and Tier-1 still reads
Δ+0.174 against the ±0.15 band — an attribution problem the golden solved differently (it moved
`SKIRT_R_FLAT` and struck the caliper, `analysis/golden/OOM-B02.md` §8) but the new run could not
fully clear inside its 2-loop budget. Second, the new run **missed the RE_SPEC interface band at
the key** (Z-KEY 1.167/1.606 mm against a ≤0.8 mm interface band), because the key block, rib and
hole were modelled as simplified boxes with a photo-inferred hole diameter, not calipered
(`B02_new_report_saved.md` §4-5). The golden's key-adjacent SAF-1 features passed at 0.316–0.751
mm, masked. The new run's tilt finding (13.7° ± 4.0°, "not resolvable") was also left unaddressed,
whereas the golden's axis fit converged to <0.001°.

## 4. Integrity caveats

- **Not fully blind.** The new skill text contains this part's golden answers — defect **D1** in
  `B02_new_report_saved.md` (`stl-re-orchestrate/references/verdict-examples.md` gives the F06
  window, hex AF, Tier-2 numbers and datum-audit numbers; `stl-re-intake-datum/references/datum-cookbook.md`
  §2.2 gives the full B02 align.py spec) and **D17** (`B02/baseline_run/` sat inside the same
  restricted directory the blind run was working in, though it was not opened).
- **CHK-INDEP:** verify ran in the same agent context that built the model — no fresh-context
  tool was available (`B02/new_run/DECISIONS.md` INDEP entry; `qa/VERDICT.md` "Independence" line).
- **The baseline agent built its own gate** because the baseline skill's own closest-point
  routine ran out of memory (15 GB) on the full mesh; the numbers above are that self-built
  KD-tree gate, not the skill's official tool (`baseline_notes.md`).
- **The gate code differs between runs.** The golden used `q20_tier2.py` (masked, ICP-refined,
  full protocol); the new run used `stl-re-verify`'s `deviation_gate.py`; the baseline used a
  hand-written KD-tree script. Face counts, masks and sample sizes are not directly comparable
  across the three (golden 185 STEP faces vs new-skill 75 build123d faces is a counting-method
  difference, not a geometry difference — see `analysis/golden/OOM-B02.md` §6, Questions).
